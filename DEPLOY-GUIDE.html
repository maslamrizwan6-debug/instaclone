📸 Put InstaClone online for free

Follow these steps once, about 20 minutes in total. At the end you get a permanent link like https://instaclone.onrender.com that works all the time.

1 · GitHubStores your website's code
2 · SupabaseDatabase + photo storage
3 · RenderRuns the website and gives you the link
4 · Keep awakeKeeps it fast, 24/7
📝 Open a notepad on your computer first. You'll copy 3 values into it along the way:
DATABASE_URL  ·  SUPABASE_URL  ·  SUPABASE_SERVICE_KEY

1 Upload the code to GitHub

⏱ about 5 minutes

  1. Download the file instaclone.zip from this workspace and unzip it on your computer. On Windows: right-click → Extract All. On Mac: double-click it.
  2. Go to github.com/signup and create a free account. Skip this if you already have one.
  3. Click the + at the top-right → New repository.
  4. Repository name: instaclone. Choose Public. Don't tick any of the other boxes. Click Create repository.
    💡 Why public? The free "keep awake" robot in step 4 only runs without limits on public repositories. Your passwords and keys are not in the code: they go into Render in step 3. So public is safe.
  5. On the next page, click the link "uploading an existing file".
  6. Open the unzipped instaclone folder on your computer. Select everything inside it (Ctrl+A on Windows, Cmd+A on Mac) and drag it onto the GitHub page.
  7. Wait until all the files have uploaded, then click Commit changes.
✅ Check: your repository page should now list public, seed, server.js, package.json and a few more files.
⚠️ server.js and package.json must be at the top level of the repository, not inside an extra folder. If you see only a single instaclone folder, open it on your computer and drag its contents instead.

2 Create the free database (Supabase)

⏱ about 5 minutes

  1. Go to supabase.com/dashboard → Continue with GitHub. This uses the account you just made.
  2. Click New project and fill in:
    FieldWhat to enter
    Project nameinstaclone
    Database passwordClick Generate a password, then copy it into your notepad. You need it in a minute.
    If you type your own password, use only letters and numbers. Symbols like @ # / ? % break the connection link.
    RegionCentral EU (Frankfurt). You'll pick Frankfurt on Render too, so the two are close together and the site stays fast.
    Then click Create new project and wait 1–2 minutes while it sets up.
  3. Get DATABASE_URL: click the Connect button at the top of your project page. Find the Session pooler connection string. It looks like this: 
    postgresql://postgres.abcdefghij:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
    Copy it into your notepad. Then replace [YOUR-PASSWORD], including the square brackets, with your database password.
    ⚠️ Use the Session pooler string, where the address ends in pooler.supabase.com. The "Direct connection" string won't work on Render.
  4. Get SUPABASE_URL: click Project Settings (⚙️ gear icon at the bottom-left) → Data API. Copy the Project URL, for example https://abcdefghij.supabase.co.
  5. Get SUPABASE_SERVICE_KEY: in Project Settings → API Keys, find Secret keys. Click to reveal one and copy it. It starts with sb_secret_.
    If you only see a service_role key (a long key starting with eyJ), that works too.
    🔒 Keep this key private. Never paste it into GitHub or share it with anyone.
✅ You don't need to create any tables or storage buckets. The website does that automatically the first time it starts.

3 Put the website online (Render)

⏱ about 5 minutes + 3 minutes waiting

  1. Go to render.com → sign up with GitHub.
  2. Click + New → Web Service → choose GitHub as the source, then select your instaclone repository.
    Don't see it? Click Configure account / Connect GitHub and give Render access to the repository.
  3. Fill in the settings:
    SettingValue
    Nameinstaclone. This becomes your link! If the name is taken, try something like instaclone-tz.
    RegionFrankfurt (EU Central)
    Branchmain
    Language / RuntimeNode
    Build Commandnpm install
    Start Commandnpm start
    Instance TypeFree
  4. Scroll down to Environment Variables and add these 3, copied from your notepad:
    Key (NAME)Value
    DATABASE_URLthe Session pooler string, with your password filled in
    SUPABASE_URLhttps://abcdefghij.supabase.co
    SUPABASE_SERVICE_KEYsb_secret_…
    Type the names exactly as shown, in capital letters, with no spaces before or after.
  5. Click Deploy Web Service. Watch the log. After 2–4 minutes you should see: 
    Created public storage bucket "instaclone-media"
Seeding demo data (first run)...
Demo data ready.
✅ InstaClone running on port 10000 (storage: Supabase)
  6. 🎉 Your permanent link is shown at the top of the Render page, for example https://instaclone.onrender.com. Open it, sign up, and share it with friends!

4 Keep it awake 24/7 (recommended)

⏱ about 2 minutes

Free Render websites go to sleep after 15 minutes with no visitors. The next visitor then waits about a minute. Supabase also pauses free databases after a week with no activity. A small free robot on GitHub that visits your site every 10 minutes fixes both.

  1. Open your instaclone repository on GitHub → Add file → Create new file.
  2. In the file name box, type exactly this. The slashes create folders automatically: 
    .github/workflows/keep-awake.yml
  3. Paste this into the big text box, and change the link on the last line to your own Render link: 
    name: Keep InstaClone awake
on:
  schedule:
    - cron: "*/10 * * * *"
  workflow_dispatch:
jobs:
  ping:
    runs-on: ubuntu-latest
    timeout-minutes: 3
    steps:
      - name: Visit the website
        run: curl -fsS --retry 3 --retry-delay 20 --max-time 90 "https://instaclone.onrender.com/api/health"
  4. Click Commit changes… → Commit changes.
  5. Go to the Actions tab. If it asks, click to enable workflows. Then click Keep InstaClone awake → Run workflow to test it. A green ✓ means it works.
💡 One free website running all month uses about 744 of Render's 750 free hours, so staying awake 24/7 fits inside the free plan. If GitHub ever emails you that the scheduled workflow was disabled (this happens after 60 days with no changes to the repository), just click to re-enable it.

? If something goes wrong

You see this in the Render logFix
DATABASE_URL is not setThe environment variable is missing or misspelled. Render → your service → Environment.
password authentication failedThe password inside DATABASE_URL is wrong, or the [ ] brackets are still there. You can set a new password in Supabase → Project Settings → Database → Reset database password.
ENETUNREACH or ENOTFOUNDYou used the "Direct connection" string. Use the Session pooler string instead.
Could not create Supabase storage bucketSUPABASE_URL or SUPABASE_SERVICE_KEY is wrong. Copy them again, with no extra spaces.
Cannot find module / build failedpackage.json isn't at the top level of the repository. Look at the warning in step 1.
The website takes ~1 minute to openIt was asleep. Set up step 4.
Email from Supabase: "project paused"Log in to Supabase and click Restore project. Step 4 stops this from happening again.

After you change an environment variable, Render restarts the site automatically. In future, any file you edit on GitHub goes live automatically within a few minutes.
